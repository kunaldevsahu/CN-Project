Reading: TTL is set by the server but enforced by every cache. dig asks the server, so it shows the new IP at once;
curl/browsers use the OS cache (mDNSResponder) and keep the old answer until it expires. A manual flush forces a new
lookup. On these Macs the cached answer lived ~37.7 s with TTL 30, so lower the TTL well before a planned change.
